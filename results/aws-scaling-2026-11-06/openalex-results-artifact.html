    Methods, definitions and limits

    Timing and QA

    ClickHouse on EC2
    Per case: one primer run (excluded), then 3 warm runs; the median of the 3 is reported. Seconds are the server-side query duration from system.query_log for each query_id, not client wall time. Warm runs discard output with --format=Null. Settings were clickhouse-client options and are not part of the SQL text. One separate cold run per case is listed but is not part of the median.
    Athena on Parquet
    Per case: 3 runs, all in the median. Seconds are TotalExecutionTimeInMillis / 1000 from the execution statistics. This includes writing results to S3 and excludes the CSV download. Result reuse was off. The SQL runs against 8 views that normalize the raw Parquet external tables at query time.
    Historical local
    Median of 5 warm runs from an earlier local setup with a different OCI image. Only family-level medians are in this payload: no per-run values, seeds, SQL text or resources.
    Graph families q05 and q06
    Each runs once per fixed seed work_id: 51557542, 24222542 and 2003585639. Table cells show the highest of the 3 seed medians, per engine. The details panel shows the selected seed separately from that family value.
    Output QA
    ClickHouse results were exported in a separate JSONEachRow run. Each Athena run's result was compared with it as a full typed multiset, so row order is not compared. Row counts and canonical SHA-256 values are listed per case.
    q02 tuning arms
    Separate job on the 31.9M cohort, 3 warm runs per arm, median reported. Settings are shown as recorded per arm.

    Resource metrics (ClickHouse runs)

    CPU
    Average busy cores over the run's telemetry window, out of the container's 18 CPUs; the share row is the same value divided by 18. Tuning summaries use the median of the 3 runs.
    Query peak memory
    ClickHouse's per-query memory peak. It excludes the OS file cache and is not container RSS. Tuning summaries use the highest of the 3 runs.
    Container sampled peaks
    Peaks of the container's total, anonymous and file-cache memory from periodic samples. Each is a separate peak, so anonymous plus file cache need not equal the total.
    Physical disk I/O
    Physical reads, writes, rates, IOPS, await and stall fraction sampled during the run. Zero physical reads in a warm run can mean the data came from the page cache; it does not mean no data was read. Await is not recorded when no I/O was sampled.
    External spill
    Compressed bytes written by external join and by external aggregation, and their total.
    Scratch used peak
    Whole-volume occupancy sampled during the run, recorded for the tuning job only. It depends on run order and is not the query's own disk usage. The load-phase peak was not recorded.
    Telemetry window
    Samples were taken about every 0.5 s. Runs shorter than that have a 2-sample window, so their rates are coarse.
    Units and nulls
    Memory in GiB (2^30 bytes). Storage, I/O, spill and scan sizes in kB, MB and GB (10^3, 10^6 and 10^9 bytes). Hover a resource value to see the exact recorded number. "Not recorded" marks a null in the source; nulls are never shown as zero.

    Limits

    • Two complete paths are compared. Storage, data layout, file format and compute all differ, so a time difference cannot be credited to the engine or the hardware alone.
    • The full corpus was not tested. The largest cohort is 6.247% of Works records, and its selected raw input is 12.635% of the snapshot's Parquet bytes. No SLA, minimum configuration or cluster sizing follows from these runs.
    • Cohorts are nested and nonrandom: each larger cohort contains the smaller ones, and none is a random sample.
    • The tuning arms ran on one cohort. memory24 changes the memory limit and both external thresholds together. No claim is made that code or configuration not recorded here was identical across arms, or across the tier and tuning jobs.
    • Historical local runs used a different OCI image and setup. They are context, not a controlled arm.
    • No new runs were made for this page. All values come from the archived records listed in section 6.
